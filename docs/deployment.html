Publishing guide

Deploy the documentation

The static documentation can be published directly with GitHub Pages. The C++ server has separate external dependencies and is not deployed by this workflow.

Add the package

Place docs/, .github/workflows/pages.yml, and the root documentation files in the repository. Review changes before committing so existing customized files are not lost.

Enable Pages

Open repository Settings, choose Pages, and set the source to GitHub Actions. Push to the main branch or manually run the workflow.

Verify the site

After the workflow succeeds, open the Pages URL, test navigation, then submit sitemap.xml in Google Search Console and Bing Webmaster Tools.

Server build boundary: the current makefile references external/private locations including /usr/local/cpp_modules, /home/tarsproto, and a Tars installation. Prepare compatible Linux, C++, Tars, MySQL client, Protobuf, RapidJSON, WBL, XGame shared modules, and generated headers before attempting a server build.

Search indexing notes

robots.txt, sitemap.xml, canonical URLs, metadata, internal links, and useful pages improve crawlability. They do not guarantee a ranking position. Indexing, content quality, reputable links, repository activity, performance, and competition remain important.
