Technical Architecture

C++ / Tars 服务架构

公开仓库是更大 XGame/Tars 体系的一部分，不是完全自包含的独立系统。

本页目录服务链路协议边界外部依赖重点风险

服务链路

客户端/网关

连接和鉴权。

Tars Servant

接口和路由。

GM/Game

服务协调。

Core

房间与玩家状态。

数据与外部服务

DBOperator 和 XGame。

接口与协议

GMServant.tars、JFGame.tars、Java2RoomProto.tars、RobotProto.tars 和 SizzlerProto.tars 描述服务边界。建议补充协议版本、错误码、兼容期、升级顺序和回滚策略。

仓库中的 *.proto.bytes 是编译资源，不是便于审阅和生成代码的原始 .proto 定义。

外部依赖

当前构建依赖 Linux、C++ 工具链、Tars、Protobuf、MySQL 客户端、RapidJSON、WBL、XGame 公共模块和生成头文件。必须以 makefile 和实际编译错误为依据记录准确版本和路径。

重点风险

入桌/离桌竞态、掉线重连、重复消息、超时、重复结算、数据库事务和协议兼容需要自动化测试。与机器人胜率或指定牌面相关的组件还需独立公平性审计和严格生产隔离。
